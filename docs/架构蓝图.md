# Jerocine 架构蓝图 (Architecture Blueprint)

> 本文档是 Jerocine 后端/前端/部署的**架构设计依据**（blueprint of record）：数据模型、分层职责、API 契约、目录树与构建顺序。契约与实现冲突时以 `server/openapi/openapi.yaml` 与实际代码为准。
> 全文标 ⚠ 处为立项时的风险/待定决策记录，随实现落地会逐步勾销；历史沿革见各节"设计取舍"说明。

---

## 1. 设计总览

**一句话定位**：**handler→service→repository(+cache decorator)→db 分层骨架 + MySQL 唯一权威真相 + Redis 纯缓存可回源 + /api/v1 语义化 REST 契约 + 物化读模型 + 边缘 HTTP 缓存**。

**刻意规避的反模式**（架构选型的出发点）：Redis 当主存（内存淘汰即空白）、单文件巨石 service、恒 200 四态契约、采集写入非原子、缓存 key 嵌分类 id。

**三条不可动摇的根原则**：
1. **MySQL 唯一权威真相**——任何可重建数据 Redis 丢失都能回源；
2. **读路径物化 + cache-aside + singleflight**——永不返回空白；
3. **公开读接口带强 HTTP 缓存语义**——跨国 RTT（服务器在新加坡）在边缘吃掉。

**关键设计取舍**：

| 维度 | 常见反模式做法（刻意规避） | 本项目采用 |
|---|---|---|
| 数据真相 | Redis 主存（开 eviction 即首页空白） | MySQL 9 表权威，Redis 纯缓存 + 协调态，开 `maxmemory 512mb` |
| 详情读 | `MovieDetail:Cid%d:Id%d`，先查 cid 再拼 key（两跳） | `v1:movie:detail:{mid}` 一跳直查 |
| 列表 | 四跳（list→basicInfo→files 回填封面） | `movie_search` 宽表 cover 进表，单次查询零回填 |
| 检索 | `LIKE %kw%` 全表扫 | FULLTEXT ngram，接口隔离可换 meilisearch |
| 采集 | 全局单 key `SearchInfoTemp` 串数据、写非原子 | per-site 暂存 + 事务双写 + 影子表 reindex |
| 契约 | 恒 200 + `{code,data,msg}` + 四态判定 | 语义化 HTTP status + RFC7807 + 单一判定 |
| 破坏性操作 | `GET /spider/reset?token=Re0` 硬编码 | `POST` + admin JWT + 二次确认 token（常量时间比较）|
| 进程内全局态 | JobRegistry 单例 / 三套内存令牌桶 / atomic 锁 | Redis 锁/桶/job 进度/token（多副本一致）|
| 配置/密钥 | 散落 init() + dev 私钥硬编码 + 端口写死 3601 | 单一 Config + fail-fast + env 驱动 |

**解决的痛点（全覆盖，✓ 已根治 / ⚠ 实现待补）**：Redis 主存✓ / key 去 cid✓ / 列表四跳✓ / 采集非原子✓ / per-site 暂存⚠ / tag 计数虚高⚠ / 缓存漏清 relate✓ / GET 破坏操作✓ / Search.go 巨石✓ / 进程内全局态⚠ / XmlCollect 空壳✓ / 死代码✓ / 配置散落✓ / BlobStore 抽象⚠ / healthcheck✓ / GOARCH 写死✓ / build:no-check✓ / 前端契约债✓。`⚠` 项见 §8 风险清单。

**存储职责切分**：
- **MySQL**：影片详情/卡片/多源/分类/采集源/任务/配置/版本/图库元数据/用户/历史/收藏/埋点——全部权威。
- **Redis db0（缓存）**：详情/卡片/首页/分类/推荐/tag 选项/多源聚合/配置缓存 + 负缓存哨兵。
- **Redis db1（协调态）**：singleflight 锁 / cron 锁 / 令牌桶 / 采集 job 进度 / 多设备 token ZSET / per-site 暂存 ZSet / 图片队列 Stream。
- **磁盘卷 `uploads`（BlobStore local）**：图片/APK 二进制（终态对象存储，`BlobStore` 接口隔离）。

## 3. 数据模型

### 3.1 MySQL 全表 DDL（golang-migrate 版本化，替代 AutoMigrate + 运行期建索引）

**全局约定**：InnoDB / `utf8mb4_unicode_ci` / `lower-case-table-names=1` / `ngram-token-size=2` / 业务表**禁 gorm 软删除**（硬删 + `state` 业务状态）/ 业务表 `created_at,updated_at BIGINT 毫秒`，user/telemetry 系列保留 `datetime(3)` / 业务主键 `mid/id` 全局唯一不嵌 cid。

|---|---|---|
| `000001_core_content` | ✓ | movie / movie_search / movie_play_source / category |

**`000001` — 内容核心（关键 DDL）**：

```sql
-- 1) movie 影片详情主表 (去 cid 维度, mid 全局唯一一跳)
CREATE TABLE movie (
  mid BIGINT NOT NULL PRIMARY KEY, cid BIGINT NOT NULL DEFAULT 0, pid BIGINT NOT NULL DEFAULT 0,
  name VARCHAR(255) NOT NULL, sub_title VARCHAR(255) NOT NULL DEFAULT '',
  c_name VARCHAR(64) NOT NULL DEFAULT '', en_name VARCHAR(255) NOT NULL DEFAULT '',
  initial VARCHAR(8) NOT NULL DEFAULT '', class_tag VARCHAR(255) NOT NULL DEFAULT '',
  area VARCHAR(64) NOT NULL DEFAULT '', language VARCHAR(64) NOT NULL DEFAULT '',
  year INT NOT NULL DEFAULT 0, actor TEXT, director TEXT, writer TEXT,
  content MEDIUMTEXT,                              -- 落库即清洗 HTML 实体/全角空格
  db_id BIGINT NOT NULL DEFAULT 0,
  db_score DECIMAL(3,1) NOT NULL DEFAULT 0,        -- ★ DECIMAL(3,1), 出参转 float64
  hits BIGINT NOT NULL DEFAULT 0, state VARCHAR(32) NOT NULL DEFAULT '',
  remarks VARCHAR(64) NOT NULL DEFAULT '',
  cover VARCHAR(512) NOT NULL DEFAULT '',          -- 封面 URL 冗余进主表
  play_from JSON, down_from VARCHAR(255) NOT NULL DEFAULT '',
  release_stamp BIGINT NOT NULL DEFAULT 0, update_stamp BIGINT NOT NULL DEFAULT 0,
  created_at BIGINT NOT NULL, updated_at BIGINT NOT NULL,
  KEY idx_pid_release(pid, release_stamp), KEY idx_pid_hits(pid, hits),
  KEY idx_pid_update(pid, update_stamp), KEY idx_cid(cid),
  FULLTEXT KEY ft_name(name, sub_title) WITH PARSER ngram
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 2) movie_search 物化卡片/检索宽表 (CQRS 读模型, mid PK 重采无冲突, cover 进表零回填)
CREATE TABLE movie_search (
  mid BIGINT NOT NULL PRIMARY KEY, cid BIGINT NOT NULL DEFAULT 0, pid BIGINT NOT NULL DEFAULT 0,
  name VARCHAR(255) NOT NULL, sub_title VARCHAR(255) NOT NULL DEFAULT '',
  c_name VARCHAR(64) NOT NULL DEFAULT '', class_tag VARCHAR(255) NOT NULL DEFAULT '',
  area VARCHAR(64) NOT NULL DEFAULT '', language VARCHAR(64) NOT NULL DEFAULT '',
  year INT NOT NULL DEFAULT 0, initial VARCHAR(8) NOT NULL DEFAULT '',
  state VARCHAR(32) NOT NULL DEFAULT '', remarks VARCHAR(64) NOT NULL DEFAULT '',
  db_score DECIMAL(3,1) NOT NULL DEFAULT 0, hits BIGINT NOT NULL DEFAULT 0,
  cover VARCHAR(512) NOT NULL DEFAULT '',          -- ★ 补 picture, 卡片自洽
  release_stamp BIGINT NOT NULL DEFAULT 0, update_stamp BIGINT NOT NULL DEFAULT 0,
  created_at BIGINT NOT NULL, updated_at BIGINT NOT NULL,
  KEY idx_pid_release(pid, release_stamp),  -- news 零 filesort
  KEY idx_pid_hits(pid, hits),              -- top
  KEY idx_pid_update(pid, update_stamp),    -- recent
  KEY idx_pid_year(pid, year),
  KEY idx_filter(pid, cid, area, language, year),  -- 多维筛选覆盖
  KEY idx_cid(cid),
  FULLTEXT KEY ft_search(name, sub_title) WITH PARSER ngram
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 3) movie_play_source 多源播放 (episodes_json 整源一行)
CREATE TABLE movie_play_source (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY, mid BIGINT NULL,
  site_id VARCHAR(64) NOT NULL, match_key VARCHAR(64) NOT NULL,  -- GenerateHashKey
  play_from VARCHAR(64) NOT NULL, episodes_json JSON NOT NULL,
  created_at BIGINT NOT NULL, updated_at BIGINT NOT NULL,
  UNIQUE KEY uk_site_match_from(site_id, match_key, play_from),
  KEY idx_mid(mid), KEY idx_match(match_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 4) category 分类父子表 (行级 CRUD)
CREATE TABLE category (
  id BIGINT NOT NULL PRIMARY KEY, pid BIGINT NOT NULL DEFAULT 0,
  name VARCHAR(64) NOT NULL, `show` TINYINT NOT NULL DEFAULT 1, sort INT NOT NULL DEFAULT 0,
  created_at BIGINT NOT NULL, updated_at BIGINT NOT NULL, KEY idx_pid(pid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 3.2 Redis key 全表（命名 `v1:{域}:{标识}`，全部带 TTL，去 cid）

写入时 TTL 全部叠 **±10% 随机抖动**（负缓存/锁 TTL 固定不抖）。

| Key 模式 | DB | 结构 | TTL | 用途 / 根治点 |
|---|---|---|---|---|
| `v1:movie:detail:{mid}` | db0 | String JSON | 24h±10% | 详情（去 cid，一跳）|
| `v1:movie:basic:{mid}` | db0 | String JSON | 24h±10% | 基本信息 |
| `v1:movie:card:{mid}` | db0 | String JSON | 6h±10% | 卡片投影 |
| `v1:cat:tree` | db0 | String JSON | 1h±10% | 分类树整树 |
| `v1:home:agg` | db0 | String JSON | 10min±10% | 首页区块化聚合 |
| `v1:classify:{pid}` | db0 | String JSON | 10min±10% | news/top/recent |
| `v1:relate:{mid}` | db0 | String JSON | 30min±10% | 推荐（**纳入失效，根治漏清**）|
| `v1:tagopts:{pid}` | db0 | String JSON | 1h±10% | tag 选项（查询期 GROUP BY）|
| `v1:play:multi:{matchKey}` | db0 | String JSON | 1h±10% | 附属站多源聚合 |
| `v1:cfg:site`/`v1:cfg:version`/`v1:cfg:sources` | db0 | String JSON | 1h±10% | 配置缓存 |
| `__nil__`（值约定） | db0 | — | 60s 固定 | 负缓存防穿透 |
| `m3u8:filtered:{sha1(src)}` | db0 | String | 10min | m3u8 过滤结果（保留）|
| `v1:lock:sf:{key}` | db1 | String NX EX5 | 5s 固定 | singleflight 防击穿 |
| `v1:lock:cron:{taskId}`/`v1:lock:sync:pic` | db1 | SET NX PX + token | 任务期 | 替代进程内重入 map/atomic 锁 |
| `v1:rl:{scope}:{ip}` | db1 | Hash(令牌桶 Lua) | 滑窗 | 统一 m3u8/login/telemetry 三桶 |
| `v1:job:{sourceId}` | db1 | Hash(total/done/failed/state) | 任务期 + GC 30min | 采集进度，替代 JobRegistry 单例 |
| `v1:token:{userId}` | db1 | ZSET(score=exp) | exp | 多设备 token ≤5 |
| `v1:queue:pic` | db1 | Stream + consumer group | — | 图片下载队列(带 ack)，替代 VirtualPicture ZSet |
| `v1:spider:temp:{siteId}` | db1 | ZSet(member=RawFilm JSON, score=mid) | 2h | **per-site 暂存，根治全局单 key 串数据** |

**淘汰/持久化**：单实例两逻辑 DB，全局策略 `volatile-lru`（只淘汰带 TTL 键——db0 缓存键全带 TTL 可淘汰，db1 协调态键也全带 TTL，内存压力下退化非损坏）。`appendonly everysec` 兜底协调态重启 + RDB `save 900 1` 暖机减冷启动击穿。

> **⚠ 待定决策（DB 拆分 vs 单实例）**：终态文字曾提「db0 allkeys-lru / db1 volatile-lru」，但 Redis 淘汰策略是**实例级而非 DB 级**，无法同实例双策略。**定稿**：单实例全局 `volatile-lru`（compose 已写死），因所有缓存键均经 `GetOrLoad` 写入且带 TTL，volatile-lru 足够且更安全。若未来出现无 TTL 缓存键需 allkeys-lru，则必须拆成两个独立 redis 实例。

## 4. API 契约总表

**全局约定（与磁盘 `openapi.yaml` 强一致）**：
- **版本**：全部 `/api/v1`。
- **参数**：camelCase，不设大写 `Pid/Category`、`link=`、`search=` 等旧式兼容映射。
- **状态码语义化**（废恒 200）：200 成功 / 201 创建 / 202 异步任务 / 204 无内容 / 304 条件请求 / 400 / 401 / 403 / 404 / 409 / 422 / 429（带 `Retry-After`）/ 5xx。
- **响应体**：成功直返 data；失败统一 RFC7807 `application/problem+json`：`{code, message, traceId, details?}`。每响应带 `X-Trace-Id`。
- **分页**：请求 `?page=&size=`（size 默认 `config.PageSizeDefaults`：home=14/classify=21/filter=49/search=10/gallery=39）；响应 `{list:[], page:{current,size,total,pageCount}}`。
- **HTTP 缓存**：公开读接口 `ETag` + `Cache-Control: public, s-maxage=300, stale-while-revalidate=600`，实现 `If-None-Match → 304`；私有/管理接口 `no-store`。

### 5.2 分层职责

- **handler**：只做绑定/校验/响应 + ETag/304；不含业务逻辑。公开读用 `writeCached`（计算 sha1 ETag，`If-None-Match` 命中返 304，否则带 `s-maxage=300, stale-while-revalidate=600`）。
- **service**：业务编排（原 logic 单例搬入）。详情 mid 直查；cache-aside 回源；首页区块化聚合（后端完成 merge/去重/随机）；tag 查询期 GROUP BY；多源 GenerateHashKey 匹配；播放默认源/默认集/越界保护。
- **repository/mysql**：唯一写 SQL 处。movie/search 双表，FULLTEXT ngram，影子表 reindex。`SearchRepository` interface 隔离便于换 meilisearch。
- **cache（★ 定稿决策 C3/2.5）**：以 **Redis 缓存层版**为唯一定稿——全局 `cache.Init(*Client)` + 包级 `GetOrLoad[T](ctx, key, ttl, loader)`（loader 返回 `(T, bool, error)` 清晰区分「不存在」vs「错误」）+ 包级 `Invalidate(DEL)` + `ErrCacheNil`。backend-service 层的 `cache.New(rdb)`/`*Cache` 实例 + `(T, error)` loader + `ErrNotFound` 版本**作废**。落地动作：`film_service.go` 全部改 `cache.GetOrLoad(ctx, key, ttl, loaderReturning(T,bool,error))`、`cache.ErrNotFound→cache.ErrCacheNil`；`main.go` 改 `db.InitRedis` 删 `cache.New/NewCoord`。Coord 统一用 `cache.TryLock`/`cache.Allow` 包级函数。
- **middleware**：Recovery 独立拆出（不再混在 Cors）；限流走 Redis 令牌桶（多副本一致）。

### 5.3 采集引擎设计要点

1. **per-site 暂存**：`v1:spider:temp:{siteId}` ZSet（member=RawFilm JSON，score=mid 去重），根治旧全局单 key `SearchInfoTemp` 多站并发串数据。
2. **事务先行双写**：`upsertOne` 在 `TxManager.WithTx` 内对 `movie + movie_search + movie_play_source` 三表 UpsertTx（原子，任一失败回滚整批）。
3. **无空窗 reindex**：全量重采走 `movie_search_next` 影子表批量 upsert → `RENAME TABLE` 原子切换；增量直接逐批事务 upsert。
4. **job 进度迁 Redis**：`v1:job:{sourceId}` Hash（total/done/failed/state），暂停/恢复/取消改 state 字段轮询（worker 每页前读），替代 JobRegistry 单例 + sync.Cond，支持多副本/重启续传。
5. **XmlCollect 补全**：`XmlCollect.GetFilmDetail` 复用 `collect.RssD` 解析（CollectApiTest 已用），根治 XML 源空壳。
6. **采集后统一失效**：`InvalidateAfterCollect` 清 `home/cat:tree` + pattern 清 `classify:*/relate:*/tagopts:*/movie:*`，**根治 RelateMovie 漏清**。
7. **删死代码**：`/provide` 路由、`SaveOriginalDetail/OriginalResource`。
8. **采集写路径锁**：单源用 `v1:lock:cron:{sourceId}`（SET NX PX + token + Lua 安全释放）替代 cron 重入 map。

> **⚠ 阻断断链（2.6）**：spider 层 `stage_job.go` 调用 `co.ZAddJSON/ZPopMin/HSet(ttl)/HIncr/HGet/Del`，但定稿的 `cache` 包未定义这些方法。**落地前必须**在 `cache` 包补全：`SpiderTempPush/Pop/Clear`（ZSet 封装）+ job Hash 方法（`JobStart/JobIncr/JobSetState/JobReadState/JobSnapshot`，字段约定统一为 `total/done/failed/state`），spider 层改调这些封装，不直接碰底层 rdb。

- `upstream jerocine_server { server server:3601; keepalive 32; }`（连接复用）。

- `proxy_cache_bypass $api_no_cache; proxy_no_cache $api_no_cache;`（带 `Authorization`/`Cookie` 跳过共享缓存，防串用户数据）。
- `proxy_cache_use_stale … updating; proxy_cache_background_update on; proxy_cache_lock on;`（永不返回空白）。

## 8. 构建顺序（有序里程碑，标注可并行与依赖）

> 阻断级缺口（必须在对应里程碑内补齐才能编译/部署）：① cache 包定稿 + spider 依赖的 ZSet/job 方法补全（M2）；② `main.go -healthcheck` 子命令（M2，否则 compose 永不 healthy）；③ nginx `/api` 前缀与后端挂载对齐（M6）；④ 三份重复 artifact 去重定稿（M0）；⑤ BlobStore 接口 + 实现（M3）。

**M0 — 契约去重定稿（前置闸门，1 人，半天）**

- M1a：`migrations/000001~000004` DDL + seed（依赖 M0 字段名）。交付物：4 对 up/down.sql，`docker compose run --rm migrate` 通过。

**M2 — 平台 + 缓存 + 仓储实现（关键路径，需先于 service/spider）**

> 下表为立项时的风险/待定决策清单。**所列各项均已随实现落地**（2026-08-03 上线验证：build/vet/test 全绿、四容器 healthy），原文保留作为决策依据。

| 级别 | 项 | 说明 / 处置 |
|---|---|---|
| 阻断（已纳入里程碑）| cache 包 spider 方法断链（2.6）| M2b 必须补 ZSet 封装 + 统一 job Hash 字段；否则 spider 无法编译 |
| 阻断 | `-healthcheck` 子命令缺失 | M2d 补 `flag.Bool("healthcheck")` 分支（内部 GET `127.0.0.1:$SERVER_PORT/healthz`，非 200 `os.Exit(1)`），否则 compose 永不 healthy、nginx depends_on 卡死 |
