# 部署指南（从零到线上）

一台全新 Ubuntu 服务器 + 一个域名，按 1→4 顺序执行即可上线。日常更新见第 5 节；命令速查见 [`deploy/README.md`](../deploy/README.md)。

> **不使用 Docker？** 本指南为 Docker Compose 方案（推荐）。同一套产物包、同一套发布语义的裸机部署见 [`deploy/bare/README.md`](../deploy/bare/README.md)。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 服务器 | Ubuntu 20.04+（x86_64），2C4G 起步，装好 Docker ≥ 24 + Docker Compose v2 |
| 代码 | `git clone https://github.com/Jerome12138/Jerocine.git` |
| 域名（可选） | 解析到服务器 IP；证书放 `deploy/certs/` 即启用 HTTPS |

> 服务器**不需要** Node / Go——构建在本机完成（应急时可用 Docker 容器在服务器上跑构建脚本，见第 5 节「应急」）。
> 前端产物构建后写入**宿主机挂载目录** `deploy/data/html`（镜像内不内置），所以首次启动后必须发布一次前端产物包（见第 3 节）。

## 2. 配置

```bash
cd deploy
cp .env.example .env    # 逐项填写，见下表
```

> 每个环境变量的完整清单（用途 / 默认值 / 必填项 / 固定值 / 改完怎么生效）见
> [`环境变量参考.md`](环境变量参考.md)。下面只列**部署前必须处理**的几项。

| 变量 | 必改 | 说明 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` / `REDIS_PASSWORD` | 🔴 | 全部换成长随机串 |
| `SPIDER_RESET_TOKEN` | 🔴 | 清库接口二次确认 token，长随机串 |
| `CORS_ALLOWED_ORIGINS` | 🟡 | 生产填 `https://你的域名`；留空 = 放行所有 Origin |
| `MYSQL_DATABASE` / `MYSQL_USER` | 🟡 | 默认 `jerocine` / `jerocine`，可保持 |
| `TMDB_LANG` / `TMDB_API_BASE` / `TMDB_IMAGE_BASE` | ⚪ | 可选；TMDB key 在后台「系统设置 → TMDB」维护，反代地址一般留空 |
| ~~`MAIL_BASE_URL` / `MAIL_DAILY_QUOTA`~~<br>~~`AUTH_TOKEN_TTL_HOURS` / `MAX_DEVICE_LOGIN` / `MAX_GOROUTINE`~~<br>~~`TELEMETRY_ALLOWED_HOSTS` / `TMDB_API_KEY`~~ | — | **均已移除（2026-10-21）**：邮件（SMTP／日配额／链接前缀）、登录策略（有效期／设备数）、采集并发、TMDB key 全部改到后台「系统设置」；埋点白名单自动取站点域名+子域 |

**JWT 密钥（RS256）**——容器以 nonroot UID 65532 运行，密钥权限不对后端起不来：

```bash
cd deploy
openssl genrsa -out secrets/jwt_private.pem 2048
openssl rsa -in secrets/jwt_private.pem -pubout -RSAPublicKey_out -out secrets/jwt_public.pem
chmod 600 secrets/*.pem
sudo chown -R 65532:65532 secrets apk    # 关键！否则 jerocine_server 读不到密钥
```

> ⚠️ 只 chown `secrets/` 和 `apk/` 这两个目录，**严禁** `chown -R <你的用户>` 整个部署目录。

## 3. 启动与验证

```bash
cd deploy
sudo docker compose --env-file .env up -d --build   # 全栈：mysql/redis → migrate → server → nginx
# 然后从本机发布一次前端（必跑，否则挂载目录空、站点 404）：
#   本机: bash scripts/deploy-web.sh
#   应急(本机也没工具链): 见第 5 节「应急」, 用容器在服务器上跑 scripts/build-web.sh 后 web-deploy
```

```bash
sudo docker compose ps                                # migrate 应为 exited(0)，其余 running/healthy
curl -sk https://localhost/ | head -5                 # 前端 200（-k：容器自持证书）
curl -sk https://localhost/api/v1/films?page=1 | head # API 冒烟
```

- 首次登录管理后台：`admin / change_me_admin`（种子迁移创建），**公网暴露后立即改密**
- 初始库**没有影片数据**：登录后在「采集管理」触发一次全量采集（或启用默认 cron）；预置的 5 个采集源为第三方 API，不可用可在后台增删/换源

## 4. HTTPS 与品牌（可选）

**HTTPS**：证书放 `deploy/certs/{fullchain,privkey}.pem`，然后 `sudo docker compose --env-file .env up -d --no-deps nginx`，
`curl -sI https://你的域名/` 期望 200。外层反代模式：改 compose 的 `nginx.ports` 映射、TLS 交给外层（一般不需要）。
老设备对 HTTPS 媒体流证书信任差：`/api/v1/m3u8/*` 已流式转发（禁缓冲不进缓存），媒体地址由后端代理下发。

**品牌定制**（`Jerocine` 只是项目代号，包名/容器名保留即可，用户看不到）：

| 改什么 | 位置 | 生效方式 |
|---|---|---|
| 站点名 / Logo / 描述 / 分享域名 | 管理后台「系统设置」 | 即时 |
| 浏览器标签标题 | `web/.env.production` 的 `VITE_APP_TITLE` | 改后本机 `bash scripts/deploy-web.sh` |
| APK 应用名 | `android/player-core/.../values/strings.xml`（两壳共用一份） | 重打 APK |
| APK 包名 | `android/app/build.gradle` 的 `applicationId` | ⚠️ 改包名 = 新应用，已装用户无法覆盖升级 |

> APK 默认服务器地址已预置官方域名（`WebShellActivity.DEFAULT_SERVER_URL` / `ServiceLocator.DEFAULT_SERVER` = `https://jerocine.art`），fork 后改成自己的域名即可；用户也可在应用内「设置 → 服务器地址」随时修改。

## 5. 日常更新

常规做法 = **本机构建 → SSH 上送 → 服务器只解包落盘**（服务器不需要任何工具链，包留档 `deploy/data/packages/`）：

```bash
# 前端（改 web/ 后）
bash scripts/deploy-web.sh              # 构建 + 上传 + 发布，一步到位
bash scripts/deploy-web.sh --pkg <tgz>  # 复用已构建好的包

# 后端（改 server/ 后）
bash scripts/deploy-server.sh           # 交叉编译 + 上传 + 发布
```

需要 SSH 别名（`~/.ssh/config` 配 `Host jerocine`）；可用 `JEROCINE_SSH_HOST` / `JEROCINE_DEPLOY_DIR` / `JEROCINE_DOWNLOAD_DIR` 覆盖默认值。

### 应急：服务器自行构建（不建议使用）

> ⚠️ go 编译/链接的内存尖峰 + 并行编译会与线上 MySQL/Redis/业务容器**抢内存和 CPU**，小内存机器可能被 OOM 误伤。仅在"本机和 CI 都不可用"时使用，并尽量低峰执行。

树上没有第二套构建配方——应急就是"让服务器当自己的 CI"：用一次性容器跑**同一份**构建脚本，产出**同格式**产物包，再走同一条发布命令：

```bash
cd /home/ubuntu/jerocine && git pull

# 后端（前端同理: node:20-alpine 容器跑 scripts/build-web.sh, 容器内先 corepack 起 pnpm9）
docker run --rm -v "$PWD:/src" -w /src -e GOPROXY=https://goproxy.cn,direct \
  golang:1.27-alpine bash scripts/build-server.sh
# → 产物包落 deploy/pkg/（与"常规"章节里的包完全同格式, 含 migrations/ 与 tooling/）

cd deploy && ./deploy.sh server-deploy deploy/pkg/jerocine-server-*.tar.gz
```

之后的流程与常规发布完全一致（自引导 → 自动迁移 → 薄运行镜像 → 等健康 → 清缓存 → 留档），回滚也用同一批留档包。

> 采集**无需手动暂停**：容器重建时 server 优雅停机（在途请求收尾 → 采集轮次取消收尾 → 新容器自动恢复增量调度）。
> 出问题整版回滚：`./deploy.sh web-rollback <TS>`（TS 见 `deploy/data/releases/`）。
> **发布边界（2026-10-22 起，树上现编译已删除）**：
> **常规**（本机构建 → 上传包 → `server-deploy`/`web-deploy`）**自包含** —— 产物包内带 `tooling/`（部署脚本 + lib + compose + Dockerfile + nginx.conf，与二进制同包同版），服务器端自动同步到固定目录 `deploy/runtime/` 并以包内版本执行：全程不 `git pull`，服务器 git 树落后/超前都不影响发版，也没有"先 push 再发布"的前置。
> 只有**旧格式包**（无 `tooling/`，例如回滚到自动迁移上线前打的包）才走 `git pull --ff-only` + 树内执行；**应急**（服务器自行构建，见上）要先 `git pull` 把树换到目标 commit。**首次部署**仍需要 `git clone`（第 1 节）—— clone 即安装动作本身。

## 常见问题

| 现象 | 处理 |
|---|---|
| 站点 404 / nginx 一直不健康 | 忘了发布前端产物包（前端是宿主机挂载目录，镜像内无产物），本机 `bash scripts/deploy-web.sh` 补一次即可 |
| `jerocine_server` 反复重启 | 99% 是权限：`secrets/`、`apk/` 必须属 `65532:65532`；`docker logs jerocine_server` 看详情 |
| 接口返回旧数据 | 两层缓存（nginx proxy_cache 7 天 + Redis DB0）——`deploy.sh` 已自动清；手动清理命令见 [deploy/README](../deploy/README.md) |
| 前端 build 失败但本地 vue-tsc 过了 | 必须用 `pnpm run build`（= `vue-tsc -p tsconfig.app.json`），裸 `tsc --noEmit` 配置宽松会漏报 |
| 迁移失败卡住 | `docker compose logs migrate`；大表建索引耗时几十秒属正常 |
| 迁移来源 | `server-deploy`/`deploy_services server` 会把迁移同步到 `data/migrations` 并自动 `up`（幂等）；`migrate` 服务挂载该目录，**不再读 git 工作树**。旧格式包（无 `migrations/`，自动迁移上线前打的）会响亮跳过迁移，用于回滚旧版 |
| Redis 缓存清空后首页短暂空白 | 缓存可安全淘汰（读路径回源 MySQL），确认 maxmemory-policy 为 `volatile-lru` |
