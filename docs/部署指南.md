# 部署指南（从零部署到服务器）

本文面向**第一次部署 Jerocine** 的用户：一台全新的 Ubuntu 服务器 + 一个域名，从零跑到线上。
日常更新命令见 [`deploy/README.md`](../deploy/README.md)；排障细节见下文[常见问题](#常见问题)。

## 一、前置条件

| 项 | 要求 |
|---|---|
| 服务器 | Ubuntu 20.04+（x86_64），2C4G 起步；安装 Docker ≥ 24 与 Docker Compose v2 |
| 代码 | `git clone https://github.com/Jerome12138/Jerocine.git`（或 SSH） |
| 域名（可选） | 解析到服务器 IP；用 HTTPS 时需要反向代理（Nginx/Caddy/1Panel 均可） |

> 服务器无需安装 Node 或 Go——前端与后端均在 Docker 多阶段构建内完成。

## 二、配置清单

进入 `deploy/`，`cp .env.example .env` 后逐项填写。**标 🔴 的必须改，标 🟡 的建议核对：**

| 变量 | 必要性 | 说明 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | 🔴 | 换掉 `change_me_root`，长随机串 |
| `MYSQL_PASSWORD` | 🔴 | 应用账号密码，长随机串 |
| `REDIS_PASSWORD` | 🔴 | 换掉 `change_me_redis` |
| `SPIDER_RESET_TOKEN` | 🔴 | 清库接口二次确认 token，长随机串 |
| `MYSQL_DATABASE` / `MYSQL_USER` | 🟡 | 默认 `FilmSite` / `jerocine`，可保持 |
| `CORS_ALLOWED_ORIGINS` | 🟡 | 生产建议填 `https://你的域名`；留空=放行所有 Origin |
| `NGINX_PORT` | 🟡 | 对外端口，默认 8080；前面有反代就保持 8080 |
| `MAX_DEVICE_LOGIN` / `AUTH_TOKEN_TTL_HOURS` | 🟡 | 设备数上限/登录态时长，默认 5 / 168h |
| `COMPOSE_PROJECT_NAME` | ⚪ | 新部署保持默认；仅从旧 `film/` 目录栈迁移时设 `film`（延续数据卷） |

**JWT 密钥（RS256）**——`.env` 之外还需生成密钥对（容器以 nonroot UID 65532 运行，读不了权限不对的文件）：

```bash
cd deploy
openssl genrsa -out secrets/jwt_private.pem 2048
openssl rsa -in secrets/jwt_private.pem -pubout -RSAPublicKey_out -out secrets/jwt_public.pem
chmod 600 secrets/*.pem
sudo chown -R 65532:65532 secrets apk   # 关键！否则后端起不来
```

> ⚠️ **严禁** `chown -R <你的用户>` 整个部署目录——只有 `secrets/` 和 `apk/` 需要 65532。

## 三、启动

```bash
cd deploy
sudo docker compose --env-file .env up -d --build
```

启动顺序自动完成：mysql/redis 健康检查 → `migrate` 一次性服务跑完 `server/migrations/` 全部版本化 DDL → 后端 `jerocine_server`（健康检查）→ 前端 `jerocine_nginx`。

```bash
sudo docker compose ps          # 五个服务：migrate 应为 exited(0)，其余 running/healthy
curl -s localhost:8080/api/v1/films?page=1 | head   # 冒烟
```

首次登录：`admin / change_me_admin`（种子迁移创建），**公网暴露后立即改密**。

## 四、HTTPS 反向代理

容器栈只监听 `:8080`（HTTP）。生产建议在宿主机用 Nginx/Caddy/1Panel 做 443 反代到 `127.0.0.1:8080` 并配证书。

> 已知约束（低版本 Android WebView/投影设备对 HTTPS 媒体流证书信任差）：站点对 `/api/v1/m3u8/proxy` 与 `/api/v1/m3u8/stream` 两个媒体路径放行 HTTP 直连，其余路径 301 到 HTTPS——反向代理配置时请保留此例外，其余路径一律跳 HTTPS。

## 五、后续更新代码

```bash
git pull
cd deploy
# 只改了前端（无中断）：
sudo docker compose --env-file .env build nginx && sudo docker compose --env-file .env up -d --no-deps nginx
# 改了后端（会重启 jerocine_server，先确认无采集任务在跑）：
sudo docker compose --env-file .env build film && sudo docker compose --env-file .env up -d server
```

后端更新后**必清两层缓存**（否则接口返回旧数据）：

```bash
# ① nginx proxy_cache（对 /api 缓存 7 天）
sudo docker exec jerocine_nginx sh -c "rm -rf /var/cache/nginx/api/* && nginx -s reload"
# ② Redis 应用层缓存（密码从 .env 读）
set -a; source .env; set +a
sudo docker exec jerocine_redis sh -c "redis-cli -a \"$REDIS_PASSWORD\" --no-auth-warning --scan --pattern 'v1:movie:*' | xargs -r redis-cli -a \"$REDIS_PASSWORD\" --no-auth-warning del"
```

## 六、服务器代码源（拉取方式）

**方式 A：服务器直连 GitHub（推荐）** —— 给仓库加只读 Deploy Key：

1. 服务器：`ssh-keygen -t ed25519 -f ~/.ssh/jerocine_deploy -N ""`，复制 `~/.ssh/jerocine_deploy.pub`；
2. GitHub 仓库页 → Settings → Deploy keys → Add deploy key，粘贴公钥，**不勾选** Allow write access；
3. 服务器 `~/.ssh/config` 加：
   ```
   Host github-jerocine
     HostName ssh.github.com
     Port 443
     User git
     IdentityFile ~/.ssh/jerocine_deploy
   ```
   （443 通道：很多机房封 `github.com:22`，`ssh.github.com:443` 是官方备用通道）
4. `git clone git@github-jerocine:Jerome12138/Jerocine.git`

**方式 B：服务器连不上 GitHub（离线搬运）** —— 本地打 bundle 推过去：

```bash
# 本地
git -C /path/to/Jerocine bundle create /tmp/jerocine.bundle main
sha256sum /tmp/jerocine.bundle
cat /tmp/jerocine.bundle | ssh user@server 'cat > /tmp/jerocine.bundle'
# 服务器：核对 sha256 后
git clone /tmp/jerocine.bundle -b main jerocine
```

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| `jerocine_server` 反复重启/起不来 | 99% 是权限：`secrets/`、`apk/` 必须属 `65532:65532`；`docker logs jerocine_server` 看具体报错 |
| 接口返回旧数据 | 两层缓存（nginx proxy_cache 7 天 + Redis），按上文清理 |
| 前端 build 失败但本地 vue-tsc 过了 | 必须用 `pnpm run build`（= `vue-tsc -p tsconfig.app.json`），裸 `tsc --noEmit` 配置宽松会漏报 |
| 迁移失败卡住 | `docker compose logs migrate`；大表加索引耗时属正常（几十秒级） |
| Redis 首页空白/淘汰告警 | 新架构下缓存可安全淘汰（读路径回源 MySQL），确认 maxmemory-policy 为 `volatile-lru` |
| 换了部署目录后出现空库/容器名冲突 | compose 项目名变了（默认取目录名）：沿用旧数据卷需设 `COMPOSE_PROJECT_NAME` 为旧项目名 |
