# 任务管理 设计（后台任务台账 + 统一管理页）

> 目标：所有定时/手动任务在管理后台可见；实时状态；失败情况与原因可查；失败可提示、可重跑。
> 适用：采集任务（定时 cron / 手动单源 / 手动补采 / 分类覆盖 / 榜单刷新）。

## 1. 现状与缺口

| 现状 | 缺口 |
|---|---|
| `cron_task` 表有 `last_run_at` 字段，但**从未被更新** | 定时任务"上次跑没跑、成没成"无从得知 |
| 采集进度在 Redis `v1:job:*`（`JobProgress`），结束态 30min 后 GC | 无持久历史；`error` 态不记原因 |
| `collect_failure` 页级失败台账（有 cause + 补采） | 只覆盖页级失败，任务级失败原因无记录 |
| 后台已有 3 个分散页面（任务监控/补采中心/定时任务） | 无统一"任务管理"入口 |

## 2. 方案：`task_run` 运行台账（DB 持久化）

新增表 `task_run`：**每次任务触发 = 一行**，覆盖 cron 触发与手动触发两类来源。

```
id, kind(cron|manual), task_type(collect|recover|category_cover|hot_refresh),
cron_id, source_id, name, hours, status(running|success|failed|canceled),
total/done/failed(页数), message(结果摘要), error(失败原因),
started_at, ended_at, created_at, updated_at
```

记录点（全部在 `SpiderService` / handler 内，nil 仓库自动跳过，不破坏既有流程）：

1. `StartCollect`（手动单源采集）→ 起一行，runOne 结束后按 `JobSnapshot` + err 收尾；
2. cron 闭包（`registerTasks`）→ 起一行（kind=cron），model 0/1 聚合 `AutoCollect/BatchCollect` 返回的摘要，model 2 用 `RecoverResult`；
3. `RecoverAsync`（手动补采）→ 起一行（kind=manual, type=recover）；
4. `CategoryCover`（分类覆盖）→ 同步起一行并收尾；
5. `HotRefresh`（榜单刷新，handler 层）→ 同步起一行并收尾；
6. `TriggerCron`（新：定时任务"立即执行"）→ 复用 cron 闭包逻辑，kind=manual。

采集源 job 快照增强（`cache/jobprogress.go`）：`JobProgress` 增加 `startedAt/hour/error`；
引擎失败路径用 `JobFail(id, msg)` 写状态 + 原因（替代裸 `JobSetState(JobError)`）。

## 3. API

- `GET /manage/tasks/runs?status=&type=&page=&size=` — 台账分页
- `GET /manage/tasks/overview` — 统计卡：运行中 / 今日成功 / 今日失败 / 待补采页数
- `POST /manage/tasks/:id/rerun` — 重跑一条历史任务（按 type 重放：collect→StartCollect(source,hours)；recover→补采全部；category_cover→覆盖分类；hot_refresh→刷榜单；cron 行按其 type 重放）
- `POST /manage/cron-tasks/:id/run` — 定时任务"立即执行"一次
- `GET /manage/spider/jobs` 增强 — 返回 startedAt/hour/error（运行中任务卡的失败原因与重跑依据）
- `GET /manage/cron-tasks` 增强 — 每条附最近一次运行（lastRunAt/lastStatus/lastError/lastMessage）

## 4. 前端页面

`/manage/tasks` 统一任务管理页（替代导航中的"任务监控/补采中心"，旧路由保留）：

- 统计卡：运行中 / 今日成功 / 今日失败 / 待补采
- Tab「运行中」：`spiderJobs` 轮询（5s 活跃/30s 空闲），失败显示原因 + 重跑
- Tab「历史记录」：`task_run` 分页表，按状态过滤；失败行红色原因 + 重跑
- Tab「失败记录」：`collect_failure` 待补采列表（精简）+ 补采按钮 + 跳转补采中心
- `/manage/cron` 定时任务页：新增"上次运行/结果"列 + "立即执行"按钮

## 5. TV 诊断（另一需求）

见 tv 端 `DeviceDiagnostics.kt` + 设置-设备面板"设备诊断"区：
设备型号 / Android 版本(SDK) / WebView(浏览器内核) 版本 / 分辨率 / 内存；
按「Android < 7.0(web APK minSdk 24) → 不支持 Web 嵌入版」与「WebView Chrome 内核过旧 → 建议独立版」给出判定与推荐。

## 6. 不做

- 按片名采集（`collect-film`）是影片级同步操作，不进台账（避免刷屏）。
- 清库（reset）为破坏性操作，不进台账。
