## 1. 注册模式（全局三态）

`site_config.register_mode`（迁移加列，默认 `off` 保守关）：

| 值 | 行为 |
|---|---|
| `off` | 关闭注册（维持现状：仅后台建号），登录页不显示注册入口 |
| `open` | 自由注册：邮箱验证通过即开号，注册完直接发 token 登录 |
| `apply` | 申请注册：验证邮箱 + 用户名 + 可选理由 → 进审核队列，管理员通过后发激活邮件，用户到站设密码才落 `users` |

开关只此一处（后台可改）；SMTP 未配置时 `open`/`apply` 实际不可用（发码直接拒绝），配置接口对前端仍如实返回 mode，由用户侧文案说明。

## 2. 数据模型

### 2.1 migration `000026_register_and_mail`

```sql
ALTER TABLE users
  ADD COLUMN email           VARCHAR(190) NULL     COMMENT '注册邮箱(可空)',
  ADD COLUMN email_verified  TINYINT(1)   NOT NULL DEFAULT 0,
  ADD UNIQUE KEY uk_users_email(email);            -- MySQL 唯一索引允许多个 NULL, 老用户兼容

CREATE TABLE IF NOT EXISTS register_apply (
  id            BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
  user_name     VARCHAR(64)  NOT NULL,
  email         VARCHAR(190) NOT NULL,
  reason        VARCHAR(500) NOT NULL DEFAULT '' COMMENT '申请人自述/邀请人, 管理员审核参考',
  source_ip     VARCHAR(45)  NOT NULL DEFAULT '' COMMENT '申请来源 IP, 供管理员识别同源批量申请',
  status        TINYINT      NOT NULL DEFAULT 0 COMMENT '0 待审 / 1 已通过 / 2 已驳回',
  reject_reason VARCHAR(255) NOT NULL DEFAULT '',
  reviewed_by   BIGINT       NULL,
  reviewed_at   DATETIME(3)  NULL,
  activated_at  DATETIME(3)  NULL COMMENT '激活完成(密码设好)时间, 审批→激活生命周期的终点',
  created_at    DATETIME(3)  NULL,
  KEY idx_apply_status_created(status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 邮件与注册开关配置(site_config 单行表, id 固定 1; 凭据列与 TmdbAPIKey 同范式)
ALTER TABLE site_config
  ADD COLUMN register_mode  VARCHAR(16) NOT NULL DEFAULT 'off' COMMENT 'off/open/apply',
  ADD COLUMN smtp_enabled   TINYINT(1)  NOT NULL DEFAULT 0,
  ADD COLUMN smtp_host      VARCHAR(190) NOT NULL DEFAULT '',
  ADD COLUMN smtp_port      INT          NOT NULL DEFAULT 465,
  ADD COLUMN smtp_secure    VARCHAR(8)   NOT NULL DEFAULT 'ssl' COMMENT 'ssl/starttls/none',
  ADD COLUMN smtp_user      VARCHAR(190) NOT NULL DEFAULT '',
  ADD COLUMN smtp_pass      VARCHAR(255) NOT NULL DEFAULT '',
  ADD COLUMN smtp_from_name VARCHAR(64)  NOT NULL DEFAULT '';
```

`register_apply` 设计要点：

- **不存密码**——申请时根本不该收密码（理由见 §9.2），审批通过也不"直接落 users"，而是走激活链接。
- 唯一约束口径：pending 状态同 email 只允许一条；被驳回后可重新提交（INSERT 前清理同 email 的 rejected 旧行）。
- 用户名只在 `users` 和 `register_apply` 各自约束；审批通过到激活的窗口期内用户名可能被 open 模式注册者占用 → **激活页强制改名**（稀有边界，见 §9.3）。

### 2.2 验证码 / 激活 / 重置凭据：只进 Redis（DB1 协调库），不落 MySQL

| 键 | 值 | TTL |
|---|---|---|
| `jc:regcode:{purpose}:{email}` | `sha256(code+pepper)`（不明文） | 300s |
| `jc:regtry:{email}` | 失败次数 | 600s |
| `jc:regsend:{email}` | 当日已发封数（邮箱级日配额） | 86400s |
| `jc:activate:{token}` | apply_id（单次消费，GETDEL） | 604800s（7 天） |
| `jc:reset:{token}`（P3） | user_id（单次消费，GETDEL） | 1800s |

purpose：`register`（P1）/ `reset`（P3 找回密码）。激活/重置是 token 不是码，理由同上：短命一次性凭据，Redis 淘汰的后果只是"用户重点一次/让管理员重发"，无一致性问题（契合"Redis 是旁路、淘汰可重建"原则）。IP 级限频走现有令牌桶。

## 3. 邮件通道与多服务商配置

### 3.1 服务商预设（内置数据，随 GET /manage/mail/config 下发）

| 预设 | host | port | 加密 | 备注 |
|---|---|---|---|---|
| QQ 邮箱 | smtp.qq.com | 465 | ssl | 须用「授权码」，非登录密码 |
| 163 邮箱 | smtp.163.com | 465 | ssl | 须用授权码 |
| Gmail | smtp.gmail.com | 587 | starttls | 须用应用专用密码 |
| Outlook | smtp.office365.com | 587 | starttls | 账号 + 密码 |
| 腾讯企业邮 | smtp.exmail.qq.com | 465 | ssl | 管理端开 SMTP |
| 阿里企业邮 | smtp.mxhichina.com | 465 | ssl | 管理端开 SMTP |
| 自定义 | 任意 | 任意 | ssl/starttls/none | 任何标准 SMTP |

预设只是默认值填充，host/port/加密/账号全部可手改——兼容性来自参数可配，不来自名单。多服务商**同时**生效（A 发 B 兜底）不做：单发件人足够，切换 = 重选预设保存（范围外，避免"到底谁在发信"含糊）。

### 3.2 实现

- `internal/platform/mailer`：`net/smtp` + `crypto/tls` 标准库，**零新依赖**。465 隐式 TLS = `tls.Dial` 后 `smtp.NewClient`；587 STARTTLS；25 明文。
- 配置结构体独立于 entity（不耦合 GORM 模型）；`Sender` 接口一行 `Send(ctx, msg)`，测试替身注入，不真发信。
- 5s 超时 + 单次重试；同步调用，失败即让调用方看到原文错误。
- 模板代码内置中文简版四封：验证码 / 激活链接 / 驳回通知 / 重置链接（P3）。不搞可配置模板（过度设计）。

### 3.3 后台「邮件设置」（凭据范式照抄 TmdbAPIKey）

- **读**：GET `/manage/mail/config` → 非凭据字段原样回 + `smtpPassMasked`（如 `a****@qq.com`）+ `smtpPassSet` bool + presets 数组。实体列 `json:"-"` 硬隔离，绝不让凭据序列化出去。
- **写**：PUT `/manage/mail/config` 独立端点；`smtpPass` 传空串 = 不修改已存值（避免掩码回显后被误清空）。
- **测试邮件**：POST `/manage/mail/test {to, ...表单当前值}` —— 用**未保存的表单值**直发一封（不用先保存，方便调参），成功/失败 + **SMTP 原文错误**回显（535 鉴权失败、连接超时等）。QQ 邮箱授权码这类坑全靠这句话定位。
- 存储与 TMDB key 同口径（DB 明文 + 接口硬隔离），不上应用层加密——保持一致，避免双标。
- `smtp_enabled` 是总开关（发现被轰炸可一键停发不清凭据）。

公开（`/api/v1`，均挂 `middleware.RateLimit` IP 桶）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/auth/register-config` | `{mode, smtpReady, presets?}`，登录页据此显隐注册入口 |

## 5. 安全规则

- 码：6 位数字、TTL 5 分钟、存哈希不明文、错 5 次锁该邮箱 10 分钟。
- 频率：同 IP 注册 5 次/10 分钟；同邮箱发码 1 分钟 1 封、日 5 封；**全局日配额默认 50 封/天（可配）**——50 封对个人站绰绰有余，真被轰炸停发比继续发好。配额对所有出站邮件（码/激活/驳回/重置/测试）统一计数。
  - 备注（2026-10-21 审查修正）：分钟窗与邮箱日计数实际按**邮件类别**（`code`/`activate`/`reject`/`reset`）分键——同一邮箱的不同类别互不挤占（否则"申请验证码"会占掉 1 分钟窗，把紧随审批的激活邮件挡在门外），单邮箱单类别仍各 5 封/日；全局日配额仍跨类别统一，且只对**真正发出**的邮件计数（含后台测试邮件，发送失败不计）。
- 激活/重置 token：`crypto/rand` 32 字节、TTL 7 天/30 分钟、单次消费（GETDEL）、重发作废旧 token。
  - 备注（2026-10-21 审查修正）：实现是"peek 只读校验 → 写库成功 → 才 DEL 消费"，而非 GETDEL 先取后放——失败不烧链接，与 §9.3 的改名重试一致。
- 注册即信任：邮箱验证 = 唯一凭据锚点。用户名沿用唯一索引；密码强度沿用登录侧现有规则（不新增规则，避免双标）。默认角色 = 普通用户（与后台建号同口径），不给 admin。
  - 备注（2026-10-21 审查修正）：`users.email` 唯一索引允许多个 NULL 但只允许一个 `''`，故后台无邮箱建号必须让该列落 **NULL**（仓储层空邮箱整列省略）；否则第二个无邮箱用户会撞唯一键。
- **登录态申请反馈（仅 apply 模式启用）**：Login 在账号不存在时按 account 查 register_apply，pending 返回 `ErrApplyPending`、rejected 返回 `ErrApplyRejected{reason}`——刻意放开的信息泄漏（申请制站点此信息半公开，且 mode=apply 才启用；off/open 一律维持笼统 401，与 disabled 现状一致）。
- `open` 模式注册成功直接发 token——复用 `Login` 的签发路径，不另造轮子。
- P3 找回密码改密成功后 `ClearUserTokens(userID)` 全端登出（旧 JWT 全失效）；后台重置密码为兜底，同样登出旧会话。

- **P2**：apply 模式 + 后台审核 Tab + 激活链路（激活页/resend）+ status 查询 + 登录即时反馈。

  - 备注（2026-10-21 落地）：按"重置链接"方案实施 —— `/auth/password/reset-link` 发一次性 token（30 分钟，Redis 协调态，peek 不消费、写成功才消费；重新申请作废旧 token）→ `/auth/password/reset` 设新密码 + `ClearUserTokens` 全端登出 → 前端 `/forgot-password` + `/reset-password`。防账号枚举（邮箱是否存在响应一致，文案中性化）。P1 预留的 `SendCode(purpose=reset)` 验证码路径保留为通用能力，本流程未接线（链接方案与激活链路同范式，不引第二套 token 语义）。

## 9. 申请制设计说明（通行做法与取舍）

### 9.1 通行四步

申请/邀请制站点的标准流程（GitLab 审核制、邀请制社区同款）：**轻量申请 → 人工审核 → 一次性激活链接邮件 → 到站设密码**。

### 9.2 为什么密码激活时才设

- 申请后可能几天才审完，用户早忘了自己设过什么——"密码错误"工单全是这么来的；激活时设当场就记得。
- 密码哈希不用在 pending 表里躺几天；pending 行没有账号保护，少一类敏感数据。
- 点链接 → 设密码 → 自动登录，一步到位，激活完成即上手。

### 9.3 申请表单字段与边界

收：邮箱（必填，身份锚点 + 通知渠道）、用户名（必填，异步查重）、理由/备注（选填，管理员参考）。管理员看到：邮箱、用户名、理由、申请时间、来源 IP。

- 用户名窗口期冲突（审批通过→激活之间被 open 注册者占用）：激活页强制改名，前端已有查重组件复用；
- pending 同 email 唯一，驳回后可重申（重申时旧 rejected 行清理）；
- 审批通过但激活邮件发送失败（配额/网络）：审批接口返回 warning 不落半程，后台列表可补发；用户侧 7 天内有效，过期用「进度查询 → 重发」。

### 9.4 用户感知（管理员几天后才回复）

三通道互补，邮件只是主通道：① 邮件：通过→激活链接（7 天），驳回→理由 + 重申入口；② 站内进度查询：登录页输邮箱，查状态、重发激活邮件——兜底"邮件进垃圾箱/换邮箱/链接过期"；③ 登录即时反馈：拿申请时的用户名尝试登录 → "审核中 / 已驳回：理由"而不是笼统错误。提交成功页文案负责预期管理（数天内回复、查收垃圾箱、可回站查进度）。

## 10. 设计决策记录（2026-10-20 两轮评审）

1. **SMTP**：多服务商预设 + 全参数可配 + 后台配置 + 测试邮件（表单值直发 + SMTP 原文错误回显）；凭据照抄 TmdbAPIKey 范式（`json:"-"`/掩码/独立写端点/留空不修改）；多服务商同时生效不做。
2. **找回密码**：P3 确认要做，改密后全端登出；后台重置密码保留兜底。
3. **注册查重错误可读化（2026-10-21 P2 落地时补）**：open 注册 / apply 申请 / activate 窗口期三类"用户名被占"原先统一返回裸 `ErrConflict`（"resource conflict"），该文案直达终端用户不可读，前端也无法区分"改名重试"与"邮箱被占"。新增哨兵 `domain.ErrUserNameTaken`（"用户名已被占用"，mapStatus 仍 409），前端激活页按 409 消息分型：用户名 → 高亮改名重试；邮箱 → 转人工处理。
4. **登录请求 silent（2026-10-21 P2）**：`POST /auth/login` 失败由页面内 errorMsg 展示，不走全局 toast —— apply 模式申请态反馈（403 审核中/已驳回）会被全局 403 文案误报成"权限不足"， misleading。
5. **找回密码走重置链接而非验证码（2026-10-21 P3 定案）**：与激活链路同范式（Redis 一次性 token、peek 只读校验、写成功才消费、重新申请作废旧 token），30 分钟 TTL；改密成功 `ClearUserTokens` 全端登出。未采用"邮箱验证码 + 新密码同页提交"方案：那会把 `SendCode(purpose=reset)` 的 5 分钟验证码语义与重置动作耦合，且 TV 端输码体验差；验证码路径保留通用能力不接线。
6. **邮件 env 只留两个兜底键（2026-10-21 P3 收尾补）**：SMTP 主体（host/port/账号/凭据/开关）全走后台 site_config，改完即热生效；env 仅兜底 `MAIL_BASE_URL`（激活/重置链接前缀，优先 site_config.domain → env → 相对路径）与 `MAIL_DAILY_QUOTA`（全局出站日配额，默认 50，即决策 3 口径）。两条部署路径（compose `server.environment` / bare-lib `server.env` 组装）均已透传，两个 `.env.example` 模板同步，bare 单测补默认值+覆盖值断言。
   - 备注（2026-10-21 同日修订）：**本条已被决策 7 取代** —— 两个键落地当天即判定不合适并删除。
7. **邮件配置零环境变量（2026-10-21 定案）**：SMTP 组 + 全局日配额 + 链接前缀全部只存 `site_config`，后台「系统 → 邮件与注册 / 站点配置」维护，保存即热生效；`MAIL_BASE_URL`、`MAIL_DAILY_QUOTA` 从 config.go / compose / bare-lib / 两个 .env.example 中移除。理由：运营阈值放部署级变量在微服务部署时最易漏配，且与"配置统一后台维护"的双轨会让人猜到底哪边生效。链接前缀固定取「站点配置 → 域名」（必须 `https://` 开头），未配则退化为相对路径。日配额存 `site_config.mail_daily_quota`（默认 50，后台可填 1~1000）。
3. **配额**：全局日配额默认 200 → **50 封/天**（对所有出站邮件统一计数）。
4. **申请制**：密码激活时设（申请表单不收密码）；申请收邮箱+用户名+可选理由+来源 IP；感知走邮件/进度查询/登录反馈三通道。
5. 原「待拍板 3 项」均已定，无遗留。
