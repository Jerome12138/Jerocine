# 账号注册功能设计（自由注册 / 申请注册 + 邮箱验证码）

> 2026-10-20 设计稿，未动工。落地顺序：P1 核心 → P2 审核 → P3 找回密码。

## 0. 结论：复杂度中等偏低，地基已齐

| 已有（无需重造） | 缺失（本次新增） |
|---|---|
| `users` 表（软删、`user_name` 唯一）、bcrypt 密码、RS256 JWT 签发/校验 | `email` 字段与唯一约束 |
| 登录/登出/设备码流、令牌撤销（Redis fail-closed） | 邮件发送通道（SMTP 客户端） |
| 令牌桶限流中间件（按 key） | 注册/发码/申请 4 个公开端点 + 3 个后台端点 |
| 版本化 migrations（`000026` 接着编号） | `register_apply` 审核表 |
| 后台用户管理页、登录页、OpenAPI 契约 | 注册模式开关（全局配置） |

新增 ≈ 2 处 DDL + 1 个平台包 + 7 个端点 + 2 个前台页 + 1 个后台 Tab + 1 个配置项。

## 1. 注册模式（全局三态）

`site_config.register_mode`（迁移加列，默认 `off` 保守关）：

| 值 | 行为 |
|---|---|
| `off` | 关闭注册（维持现状：仅后台建号），登录页不显示注册入口 |
| `open` | 自由注册：验证邮箱通过即开号，注册完直接发 token 登录 |
| `apply` | 申请注册：验证邮箱 + 填申请理由 → 进审核队列，管理员通过后才落 `users` |

开关只此一处（后台可改）；SMTP 未配置时 `open`/`apply` 实际不可用（发码直接拒绝），
配置接口对前端仍如实返回 mode，由用户侧文案说明。

## 2. 数据模型

### 2.1 migration `000026_register_email`

```sql
ALTER TABLE users
  ADD COLUMN email           VARCHAR(190) NULL     COMMENT '注册邮箱(可空)',
  ADD COLUMN email_verified  TINYINT(1)   NOT NULL DEFAULT 0,
  ADD UNIQUE KEY uk_users_email(email);            -- MySQL 唯一索引允许多个 NULL, 老用户兼容

CREATE TABLE IF NOT EXISTS register_apply (
  id           BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
  user_name    VARCHAR(64)  NOT NULL,
  email        VARCHAR(190) NOT NULL,
  password     VARCHAR(255) NOT NULL COMMENT '提交时即 bcrypt, 审批通过直接落 users',
  reason       VARCHAR(500) NOT NULL DEFAULT '',
  status       TINYINT      NOT NULL DEFAULT 0 COMMENT '0 待审 / 1 已通过 / 2 已驳回',
  reject_reason VARCHAR(255) NOT NULL DEFAULT '',
  reviewed_by  BIGINT       NULL,
  reviewed_at  DATETIME(3)  NULL,
  created_at   DATETIME(3)  NULL,
  KEY idx_apply_status_created(status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

`register_apply` 唯一约束口径：按 `email` 查重防重复提交（pending 状态同 email 只允许一条；
被驳回后可重新提交，INSERT 前先清理旧 rejected 行或改唯一键带 status 派生列——实现时定）。

### 2.2 验证码：只进 Redis（DB1 协调库），不落 MySQL

| 键 | 值 | TTL |
|---|---|---|
| `jc:regcode:{purpose}:{email}` | `sha256(code+pepper)`（不明文） | 300s |
| `jc:regtry:{email}` | 失败次数 | 600s |
| `jc:regsend:{email}` | 当日已发封数（日配额） | 86400s |

purpose：`register`（本期）/ `reset`（P3 找回密码复用）。理由：码是短命一次性凭据，
Redis 淘汰/丢失的后果只是"用户重点一次获取"，无一致性问题（契合既有"Redis 是旁路、
淘汰可重建"原则）；IP 级限频走现有令牌桶，邮箱级 1 封/分钟 + 5 封/天在 Redis 计数。

## 3. 邮件通道 `internal/platform/mailer`

- `net/smtcp` 标准库实现，**不引第三方依赖**；QQ 邮箱/163/企业邮均可（465 SSL 或 587 STARTTLS，
  25 端口在云服务器基本被墙，配 465）。
- 凭证走环境变量 `SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASS/SMTP_FROM`，进 `.env` 不进 git；
  distroless 容器无本地 MTA 不影响——外网 SMTP 通即可。
- `Send(ctx, to, subject, body)`：5s 超时 + 单次重试；同步调用，失败即回"验证码发送失败"。
- 模板代码内置中文简版（标题 + 6 位码 + 5 分钟有效期），不搞可配置模板（过度设计）。

## 4. 端点

公开（`/api/v1`，均挂 `middleware.RateLimit` IP 桶）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/auth/register-config` | `{mode, smtpReady}`，登录页据此显隐注册入口 |
| POST | `/auth/register/code` | `{email}` 发码；桶 + 邮箱 1/min、5/day + 代码日配额 |
| POST | `/auth/register` | open 模式：`{userName, password, email, code}` → 校验码 → 落 users（`email_verified=1`）→ 直接返回 token |
| POST | `/auth/register/apply` | apply 模式：`{…, reason}` → 落 `register_apply`(pending) |
| GET | `/auth/apply/status` | `?email=` 查申请状态（待审/通过/驳回+理由），前端轮询 |

管理（`AuthToken` + `RequireAdmin`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/manage/register/applies` | pending 列表（分页，带 email/user_name） |
| POST | `/manage/register/applies/:id/approve` | 事务：校验 pending → 落 users → apply=approved + reviewed_by/at |
| POST | `/manage/register/applies/:id/reject` | `{reason}` → apply=rejected + 理由落库 |

后台原有 `CreateUser` 保持（补可选 email 参数，管理员手工建号不强制验证邮箱）。

## 5. 安全规则

- 码：6 位数字、TTL 5 分钟、存哈希不明文、错 5 次锁该邮箱 10 分钟（`jc:regtry`）。
- 频率：同 IP 注册 5 次/10 分钟；同邮箱发码 1 分钟 1 封、日 5 封；全局日配额默认 200 封（可配，防邮箱轰炸）。
- 注册即信任：邮箱验证 = 唯一凭据锚点。用户名沿用现有唯一索引；密码强度沿用登录侧现有规则（不新增规则，避免双标）。
- 申请模式防重：pending 同 email 唯一；密码提交时即哈希，审核员看不到明文。
- `open` 模式注册成功直接发 token——复用 `Login` 的签发路径（多设备集合登记一致），不另造轮子。

## 6. 前端

- **LoginView**：`register-config` 拉模式；`open`/`apply` 显示"注册账号"入口，`off` 不显示。
- **新增 RegisterView.vue**（public 路由 `/register`）：账号 / 密码 / 邮箱 / 验证码（"获取验证码"带 60s 冷却）/（apply 模式）申请理由。
  - open 模式提交成功 → 直接进首页（已登录态）；
  - apply 模式提交成功 → "审核中"状态页，轮询 `/auth/apply/status`，驳回时显示理由、可改后重新提交。
- **后台 manage/user**：新增"注册审核" Tab——pending 列表 + 通过/驳回（驳回必填理由）。
- **壳无需改动**：TV/原生壳页面随 web 分发；SettingsView 只有登录态判断，无感。

## 7. 测试与验收

- service 层表驱动：码生成/校验/过期/超限锁邮箱/模式开关分支/审批事务（审批重复点=幂等拒绝）；
- handler 层：参数校验 + 限流命中 → 429 + 统一错误码（复用 `dto.Error` / `domain.ErrXxx`）；
- mailer：fake SMTP（`net/smtp` 客户端难 mock ⇒ 抽 `Sender` 接口，测试替身注入，不真发信）；
- e2e：open 模式全链路（发码→注册→带 token 访问 `/me`）；apply 模式全链路（提交→审核通过→登录）。
- OpenAPI 同步（server/openapi）。

## 8. 分阶段

- **P1 核心**：mode 配置 + mailer + open 注册 + 码全链路 + 迁移 + LoginView 入口。
- **P2**：apply 模式 + 后台审核 Tab + status 查询。
- **P3 可选**：邮箱找回密码（复用 purpose=reset）、审批结果邮件通知、注册协议勾选。
