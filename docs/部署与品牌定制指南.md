# 部署与品牌定制指南

> 面向想独立部署本项目的用户：从零跑起，并把站点改成自己的品牌。核心原则：**代码里不固化任何品牌**（保留的 Jerocine 只是项目代号），你要改的都在下面这几处。
> 更新时间：2026-09-17。

## 1. 快速开始（全新部署）

```bash
# 0) 前置：Docker + Compose、域名证书（放 deploy/certs/fullchain.pem + privkey.pem）
git clone https://github.com/Jerome12138/Jerocine.git
cd Jerocine

# 1) 部署配置：填你自己的值
cp deploy/.env.example deploy/.env
#   改 .env 里的密码 / JWT 密钥路径 / 埋点白名单（见 §3.1）

# 2) 生成 JWT 密钥（RS256，路径与 .env 一致，属主必须是 65532:65532）
openssl genrsa -out deploy/secrets/jwt_private.pem 2048
openssl rsa -in deploy/secrets/jwt_private.pem -pubout -RSAPublicKey_out -out deploy/secrets/jwt_public.pem
chown 65532:65532 deploy/secrets/*.pem

# 3) 启动全栈（自动跑迁移；nginx 直接监听 443 终结 TLS）
cd deploy && ./deploy.sh

# 4) 后台改品牌：浏览器打开 https://你的域名/admin（或站内管理入口），
#    在「系统设置」改站点名 / Logo / 描述 / 域名 —— 运行时生效，无需改代码
```

启动后站点即可用。前端代码默认用 `VITE_APP_TITLE`（构建期）和后台 `site_config`（运行期）两个来源，后者优先。

## 2. 品牌定制：要改的位置（全部清单）

**目标：任何个人品牌只出现在下面 3~4 个文件里，代码本身无品牌残留。**

| # | 位置 | 改什么 | 生效方式 | 必须改？ |
|---|---|---|---|---|
| 1 | `deploy/.env` | 密码、JWT 路径、埋点白名单（域名相关） | 重启容器 | ✅ 必须 |
| 2 | 管理后台「系统设置」 | **站点名 / Logo / 描述 / 域名** | 运行时即时生效 | ✅ 必须（这是用户看到的品牌） |
| 3 | `web/.env.production` | `VITE_APP_TITLE`（浏览器标签标题，默认 Jerocine） | 重新构建前端（`./deploy.sh nginx`） | 建议 |
| 4 | APK 打包（可选，不打 APK 忽略） | 应用名 / 包名 / 默认服务器地址（见 §3.4） | 重新打包 | 打 APK 才需要 |

> 说明：`Jerocine` 在代码里保留的只是**项目代号**（包名、容器名、协议标识），部署者无需也不能通过它改品牌——品牌由 #2 后台配置决定。

## 3. 各修改点详解

### 3.1 `deploy/.env`（部署配置）

| 变量 | 说明 |
|---|---|
| `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` / `REDIS_PASSWORD` | 数据库与 Redis 密码，必改 |
| `JWT_PRIVATE_KEY_FILE` / `JWT_PUBLIC_KEY_FILE` | JWT 密钥挂载路径，一般保持默认 |
| `SPIDER_RESET_TOKEN` | 清库接口二次确认 token，必改为长随机串 |
| `AUTH_TOKEN_TTL_HOURS` / `MAX_DEVICE_LOGIN` | 登录态时长 / 每账号设备上限 |
| `CORS_ALLOWED_ORIGINS` | CORS 白名单（逗号分隔；空 = 放行所有 Origin） |
| `COMPOSE_PROJECT_NAME` | 默认 `jerocine`；从旧栈迁移时才需改（延续数据卷） |

**域名**：不需要在 `.env` 配域名。TLS 由 nginx 容器直接终结，证书放 `deploy/certs/{fullchain,privkey}.pem`（nginx `server_name _` 通配，见 `deploy/data/nginx/nginx.conf`）。域名只影响：①证书内容；②后台「系统设置」的 domain 字段；③后端埋点白名单 `TELEMETRY_ALLOWED_HOSTS`（如启用埋点，在 `.env` 加该变量，逗号分隔）。

### 3.2 管理后台「系统设置」（站点品牌）

- **site_name**：站点显示名（顶栏、管理端侧边栏、各端标题）
- **logo / description / domain**：Logo 图、描述、对外域名
- 修改后立即生效（`site_config` 缓存自动失效），无需重启。

### 3.3 `web/.env.production`（构建期）

```ini
VITE_API_BASE=/api
VITE_APP_TITLE=你的站点名      # 浏览器标签标题，默认 Jerocine
```

改后重新部署前端：`cd deploy && ./deploy.sh nginx`。

### 3.4 APK 打包（可选）

Web 本身就是 PWA（可直接安装）；要出原生 APK 时，改：

- **应用显示名**：`tv/app/src/main/res/values/strings.xml` 与 `web/android/app/src/main/res/values/strings.xml` 的 `app_name`（默认 "Jerocine影视"）
- **包名**：`tv/app/build.gradle.kts` 与 `web/android/app/build.gradle` 的 `namespace` / `applicationId`（默认 `com.jerocine.tv` / `art.jerocine.tv`、`com.jerocine.app` / `art.jerocine.app`）
  - ⚠️ 改包名 = 新应用，已安装用户无法覆盖升级，自行权衡
- **默认服务器地址**：`tv/app/src/main/java/com/jerocine/tv/data/ServiceLocator.kt` 与 `web/android/app/src/main/java/com/jerocine/app/MainActivity.java` 的 `DEFAULT_SERVER`（默认 `https://jerocine.art`）
  - 推荐：留空，让用户首次启动输入自己的服务器地址（APK 已支持手动输入）

> 待办（规划中）：以上 3 处将参数化收敛到 `gradle.properties` 一个文件，届时打 APK 只需改 1 处。

## 4. 常见部署形态

| 形态 | 说明 |
|---|---|
| 纯 Web（推荐起步） | 不碰 APK，浏览器/PWA 使用；步骤 §1 即可 |
| 多端（Web + TV + 手机 APK） | Web 构建时指定 API 地址；APK 打包改 §3.4 三处 |
| 已有域名 / HTTPS 证书 | 证书放 `deploy/certs/`，重启 nginx 即可 |
