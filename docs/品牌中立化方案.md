# 品牌中立化与配置化方案

> 目标：让任何人 clone 本仓库后，改少量几处即可部署为自己的影视站，代码内不固化任何人的品牌名。
> 状态：**已定案并部分实施**（2026-09-17）。结论：保留 Jerocine 作项目代号，`gf-` 前缀已全仓替换为 `jc-`（提交 `983993f`）；品牌层配置化清单见《部署与品牌定制指南》。

## 0. 问题与结论

Jerocine 被固化在 157 个文件中，且 `gf-` 设计令牌前缀（116 文件 + 94 文件 `gf_`）源于旧项目代号 "go film"。

**决策（2026-09-17 撞名验证后）：**

1. **保留 Jerocine 作项目代号**。撞名检索：Jerocine 无任何同名软件/项目/产品（仅个别自然人姓名），全球唯一性极好；而通用词根（cine / cinebox / opencine 等）严重撞名（App Store 两个 CineBox、Crytek Cinebox 团队等）。Jerocine 语义贴切（Jerome + cine）、中英文可读、零改名成本（包名/容器/DB/域名/证书/线上 APK 全部沿用）。开源项目代号带作者印记是常态（Linux/Django/Curl），关键在品牌层可配置。
2. **`gf-` → `jc-`**（Jerocine 首字母缩写，与代号呼应）：`--jc-list-cols`、`jc-card-grid`、`jc_play`。
3. **品牌层配置化**（见下），部署者改少量几处即可。

## 1. 三层标识解耦

```
品牌层（显示，部署者必改）   → site_config(DB) + VITE_APP_TITLE(构建) + APK 参数
项目代号层（内部，固定）     → Jerocine: 仓库名/容器名/包名/协议标识/默认域
设计令牌层（内部，固定）     → jc- / jc_（已替换完成）
```

## 3. 部署者改动清单（当前现状，详见《部署与品牌定制指南》）

部署者需要改的位置（已尽量集中，每端 1 处）：

1. `deploy/.env`：域名、数据库/Redis 密码、JWT 密钥路径、埋点白名单
2. 管理后台「系统设置」：站点名、Logo、描述、域名（运行时生效，不改代码）
3. `web/.env.production`：`VITE_APP_TITLE`（浏览器标签标题）
4. APK 打包（可选，不打 APK 可忽略）：
   - `tv/app/src/main/res/values/strings.xml`：`app_name`（应用显示名）
   - `tv/app/build.gradle.kts` + `web/android/app/build.gradle`：包名
   - 默认服务器地址（建议改为首次启动引导输入，见 §5 待办）
