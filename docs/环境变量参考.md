# 环境变量参考（唯一权威清单）

本文件是**唯一**完整清单。`.env.example` 是"要你填的模板"，这里是"每个键是什么、给不给默认值、改完怎么生效"。

> **新增/删除一个 env 时必须同步 5 处**，漏一处就是"填了不生效"或"只在这个部署模式里有"：
> ① 本文档 ② `deploy/.env.example` ③ `deploy/bare/bare.env.example`
> ④ `deploy/docker-compose.yml` 的 `server.environment`（**显式列表，没有 env_file**）
> ⑤ `deploy/bare/bare-lib.sh` 的 `bare_derive_server_env`（heredoc，与 ④ 逐项对应）
> 另外 `deploy/tests/bare-deploy.test.sh` 有断言，加键时顺手补。

## 0. 什么该进 env、什么该进后台？

判据：**进程启动期就要用的 → env；运营参数 → site_config（后台，保存即热生效）**。

| 层 | 内容 | 放哪 |
|---|---|---|
| L0 引导与密钥 | DB/Redis 连接、JWT 密钥、运维 token | env / secret manager（DB 连不上起不来；密钥与锁不能同放） |
| L1 部署拓扑 | 端口、挂载路径、时区、运行模式、安装前缀 | env |
| L2 运营参数 | 注册模式、SMTP、邮件配额、站点信息、**登录策略、采集并发、TMDB key** | 后台 `site_config` |
| L3 构建期 | APK 版本号等不可变产物信息 | 构建注入 |

**后台已接管（不用 env）**：站点名 / 域名 / logo / SEO / 维护状态、注册模式、SMTP 七项、邮件日配额、
TMDB API Key、**登录有效期与设备数（系统设置 → 账号与安全）**、**采集并发（→ 采集性能）**。

## 1. 部署前必须配置（无默认值，缺了进程起不来）

| 变量 | 适用 | 用途 | 缺失后果 |
|---|---|---|---|
| `MYSQL_ROOT_PASSWORD` | compose | MySQL root 密码（仅初始化数据卷时用，应用不读） | mysql 容器起不来 |
| `MYSQL_PASSWORD` | 两种 | 应用账号密码；compose 拼进 `MYSQL_DSN`，bare 用它建库用户 | DSN 拼不出来 / fail-fast |
| `REDIS_PASSWORD` | 两种 | Redis 密码（redis 与 server 共用） | 起不来 |
| JWT 密钥对 | 两种 | RS256 签名/验签。`JWT_PRIVATE_KEY`+`JWT_PUBLIC_KEY` 或 `*_FILE`（传路径）二选一 | fail-fast |
| `SPIDER_RESET_TOKEN` | 两种 | 清库接口 `/api/v1/manage/spider/reset` 的二次确认 token | fail-fast |

- `MYSQL_DATABASE` / `MYSQL_USER` 默认 `jerocine` / `jerocine`，一般不用改（DSN 由它们拼）。
- **compose 模式不要手填 `MYSQL_DSN`**；bare 也不要——`bare-lib.sh` 自动组装成 `127.0.0.1:3306`。

## 2. 建议按环境调整（有默认值）

| 变量 | 默认 | 用途 | 什么时候必须动 |
|---|---|---|---|
| `CORS_ALLOWED_ORIGINS` | 空（放行所有 Origin） | 跨域白名单，逗号分隔，须含 scheme 且精确匹配（浏览器 Origin 无尾斜杠） | 2026-10-28 起生产已收敛为 `https://jerocine.art,https://www.jerocine.art,https://web.jerocine.art`（web 二级域 = EdgeOne 前端）；原生 App 请求不带 Origin，不受白名单影响 |
| `TMDB_LANG` | `zh-CN` | TMDB 检索语言 | 多语言站（基本不会改，与两个 BASE 放一起） |
| `TMDB_API_BASE` | 空（官方 `api.themoviedb.org/3`） | TMDB API 反代地址 | 墙内自建反代 |
| `TMDB_IMAGE_BASE` | 空（官方 `image.tmdb.org/t/p/`） | TMDB 图床反代地址 | 同上 |
| `DANMU_SERVICE_URL` | `http://danmu:3611` | danmu-service（Node 弹幕壳）基址，**L1 拓扑** | 仅本地联调（server 跑在 compose 外）时改 `http://127.0.0.1:3611`；bare 模式由 bare-lib.sh 生成 `http://127.0.0.1:3611` |
| `REDIS_MAXMEMORY` | `512mb` | Redis 内存上限（compose command / bare redis.conf，server 不读） | 内存小或大 |
| `PREFIX` | `/opt/jerocine` | **仅 bare**：安装根目录 | 换安装位置 |

> `TMDB_API_KEY` 已删除：key 只存 `site_config`，后台「系统设置 → TMDB」维护，保存即热替换。
> **升级坑**：以前把 key 配在 `.env` 里的部署，升级后数据库里是空的 —— 后台会显示「未配置」、横图回填停摆。
> 到后台重存一次即可（凭据不再有 env 兜底，所以后台是唯一权威）。
>
> `DANMU_SERVICE_URL` 说明：compose 模式下 server.environment 已写死 `http://danmu:3611`（与 `REDIS_ADDR` 同风格），
> 改它是为了本地联调；**bare 模式当前不含 danmu-service**（无 systemd 单元/部署脚本），连不上时 Go 网关
> 静默降级"暂无弹幕"（不阻塞播放、不报错），属预期行为。danmu 发布见部署指南「danmu-service 发布」一节。

## 3. 固定值（知道即可，不要改）

| 变量 | 值 | 为什么不能改 |
|---|---|---|
| `SERVER_PORT` | `3601` | nginx upstream、容器 healthcheck、bare systemd 全按它写死 |
| `REDIS_DB_CACHE` / `REDIS_DB_COORD` | `0` / `1` | 代码强制两者必须不同；DB0=缓存（部署脚本 `FLUSHDB -n 0` 写死）、DB1=协调态（**禁动**） |
| `BLOB_DRIVER` / `BLOB_LOCAL_DIR` / `BLOB_BASE_URL` | `local` / 挂载点 / `/api/upload/` | 与 docker 卷 / bare 目录、nginx `/api/upload/` 路由绑定 |
| `JWT_ISSUER` | `Jerocine` | 已签发 token 的 `iss` 声明 |
| `GIN_MODE` | `release` | 调试模式会打详细日志、影响性能 |
| `TZ` | `Asia/Shanghai` | 定时任务、邮件日配额都按本地日期切天 |

## 4. 只被部署脚本/容器读取（server 进程不读）

| 变量 | 读取方 | 说明 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | compose mysql 服务 | 只在初始化数据卷时生效；之后改它不会改已有库密码 |
| `MYSQL_DATABASE` / `MYSQL_USER` | compose mysql 服务 + DSN 拼接 / bare 建库 | 见上 |
| `REDIS_MAXMEMORY` | compose redis command / bare redis.conf | 见上 |
| `PREFIX` | bare `install.sh` / systemd unit / `bare-lib.sh` | 见上 |
| `MIGRATE_BIN` | bare `migrate.sh` | 缺省找 `/usr/local/bin/migrate` |
| `COMPOSE_PROJECT_NAME` | compose | 默认 `jerocine`；老栈（`film_*` 数据卷/容器）迁移时才设 `film` |

## 6. 改完怎么生效

- **env 只在进程启动时读一次**：改完必须重启——compose `sudo docker compose up -d --no-deps server`，bare `systemctl restart jerocine-server`。
- **后台配置保存即生效**，但有三项是"下次才生效"，界面上也标注了：
  - 登录有效期：只影响之后新签发的 token，已登录设备按原到期时间失效；
  - 设备数上限：**下次登录**时按新值裁掉最旧设备，不会立即踢人；
  - 采集并发：**下一轮采集**生效，不打断进行中的轮次（总上限与主站/从站硬上限三项目前都在后台「采集性能」卡片可改）。
- 核对当前生效值：server 启动日志的脱敏摘要 `Config{...}`；运营参数看后台页面。
- 踢人：后台「系统设置 → 在线会话」可看当前登录凭据（用户 / IP / UA / 登录时间 / 最近活跃）并单设备踢下线。

## 7. 三个已踩过的坑

1. **compose 的 `server.environment` 是显式列表、没有 `env_file`**：往 `.env` 里加键但没在这里透传，容器里根本看不到（踩过 `MAIL_*`、`TMDB_API_BASE`）。
2. **bare 侧对应的是 `bare-lib.sh` 的 heredoc**，同样不会自动搬运，两处必须同时改。
3. **改完不重启 = 没生效**，这是最常见的"我明明配了"。
